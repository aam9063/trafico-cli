| minor | `internal/datex2/sections.go` | If the description element is **absent**, matching on an empty string would have been vacuously false and rejected — but only by accident, not by intent. | **Applied.** The absent case has its own guard and its own error message. `TestParseTefivaSectionsRejectsMissingFeedDescription` strips the block from the tefiva fixture and pins it. |

Verified by execution, no findings:

- **The match cannot false-positive on a third feed** without that feed's frozen description literally containing the DGT's own brand token. Generic words are excluded on purpose — "tramos", "animales" and "publicación" all appear in motos prose, so matching any of them would have reproduced the bug.
- **No existing test had to change.** TEFIVA still parses, and INVIVE, radars, situations and empty bodies are still rejected.
- **The fixture is a real snapshot**, 2 of the 97 references, XML-verified, and it carries the prose that distinguishes it. It is the only fixture in the repository taken from a feed the project does not emit.
- **`check.sh --strict` is green.**

## Veredicto

**Approve.** This closes the third instance of the same failure class, and it was the only one found by a review rather than by writing the parser: the INVIVE/radars blocker was caught during implementation, and this one arrived as a non-blocking advisory on FEED-05 that had to be measured to become real.

Worth recording: the advisory said "unverified", which is easy to file away as a note. The feed said otherwise.

### Not verified

- The other 95 motos references: the pattern was checked against all 97 ids, but the fixture carries two.
- A future DGT reword of the description: if the brand token disappears, a legitimate feed starts failing. That is the chosen direction, and the error message quotes the observed prose so the cause is obvious.
- The release published as `v0.1.0` **predates this fix**. Anyone running `trafico sections --kind animals` against the motos URL is unaffected in practice (it is a different configured URL), but the published binary carries the weaker guard.
