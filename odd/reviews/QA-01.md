Advisories inherited from earlier reviews, re-judged here:

- `install.sh:97` (flagged as `:85` — line drift) — release parsing without `jq`. **Noise.** The `sed` parse is fail-closed (no match dies with a message naming the `TRAFICO_VERSION` escape hatch), GitHub's `latest.json` is flat, and `head -n 1` over the single `tag_name` occurrence is safe. When the API shape changes, the failure mode is a clean abort — the direction an installer should fail in.
- `scripts/test-install.sh:53` (inside the `expect_eq` helper, `:45-56`) — **the helper is noise**: a plain TAP-style assertion. **What is not noise**, already flagged in REL-01's "Not verified": the 31-assertion harness runs in no gate — nothing forces it before a release. That is REF-3 below.
- `internal/datex2/sections.go:378-394` — a repeated `com:feedDescription` silently keeps the last. **Noise.** The feed publishes exactly one (docs/feeds.md §8); multiple `com:value` blocks inside one element are already handled by `tefivaDescriptionValue`; and the identity match is fail-closed (`Contains("tefiva")`), so even a hostile or reworded repeat can only produce exit 7, never a wrong-dataset acceptance. Three decisions of this session, judged as a whole:

1. **`internal/cli/render.go` at 976 lines — should change (REF-2).** The shape inside the file is consistent: every renderer obeys the same three laws (type-assert the response, build to a `strings.Builder`, close with the attribution line), and the helpers are genuinely shared, not co-located — `formatPK` serves incidents, route check, radars and watch targets; `truncationNote` serves six renderers; `truncateText` even reaches `doctor.go`'s config line through `textColumnWidth` aliased to `descriptionColumnWidth` (`schema.go:162`). The problem is not the quality of any renderer, it is the unit of change: the three passes that wrote the file each appended, and the next one will too, because the file's own header invites it. The seam is real and already proven by the FORMAT-01 renderers living beside their commands. Nothing here must be fixed before the next release — the tests pin the behaviour — but the file has crossed the size at which apposition stops being free.
2. **`internal/cli` importing `internal/store` — accepted with cost.** FORMAT-03's review claimed this import was new; it was not. `cli/watch.go:706-715` (`loadStoreContext`, `store.Open`) and the `store.WatchKind*` constants (`watch.go:505-517`) already crossed that boundary when the watch commands landed, so FORMAT-03 extended an existing direction rather than opening one. The honest statement of the boundary today is: `app` is a validation/translation layer over `store`, the CLI holds the `store.Open` handle and passes it through, and `app` returns `store.Event`/`store.Watch` to the CLI un-translated. That is a thinner `app` than the ARRANQUE §8.2 diagram implies, but it is coherent, and `internal/store` is a local storage package, not a network or XML edge — no principle P-01..P-09 is at stake. The alternative worth naming was never a view type in `internal/model`: `model` is the frozen JSON contract (P-09), and polluting it with storage types would be worse than the current coupling. The cheap cut, if this ever hurts, is for `app` to return its own event view; at the current size it does not hurt.
3. **Unexported fields on the response structs (`watchCheckResponse.eventsDetail`, `serviceResponse.verb`) — accepted with cost.** The mechanism is sound: `encoding/json` skips unexported fields, so `--json` stays byte-identical with no `schema_version` bump, and the same-package tests can construct the structs. The cost is that the transport struct now has two roles, and the guard against misuse is only a comment — an accidental capitalisation (`EventsDetail`) would silently widen the contract. What keeps that risk bounded is real: the watch envelope keys are pinned by the existing watch tests, and the FORMAT-03 review already recorded the pattern as known debt. Do not replicate it further: the moment a third command needs renderer-only state, extract view types — the move is mechanical, and REF-2 is the natural vehicle.
